# Cloud operations and private recovery

The world owns auxiliary SQLite counters and recovery barriers. `/api/v1/operations` requires operator Access authentication; `/api/v1/public/analytics` returns daily entity request counts, errors and aggregate elapsed time. Traffic has `unclassified`, `internal` or `synthetic` provenance. External requests are unclassified: counts cannot establish human visitors or unique people. IP addresses, paths, queries, user agents and request IDs are absent from public aggregates. Trusted internal receipt IDs deduplicate delivery for one day.

`recordModelUsage` records provider-reported prompt/completion token counts once per receipt. Configure both model input/output USD-per-million rates to settle measured inference costs; without verified rates or returned token usage, the reservation remains charged conservatively for operator reconciliation. Provider invoices remain separate evidence.

Live turns increment exactly their observed bounded-loop outcome: `entity.turn_completed`, `entity.turn_blocked` or `entity.turn_step_limit`. Thrown errors or invalid runtime results increment `entity.turn_failure`. Completion means the loop returned without further tool calls; it does not prove useful work, publication or goal completion. Historical `entity.turn_success` counters remain readable but are no longer incremented. The scheduler and setup tooling share `turn-outcome.ts`; focused checks exercise actual bounded-loop completion, consecutive failures and step exhaustion in `turn-outcome.test.ts`.

## Daily complete backup

Set `BACKUPS_ENABLED=true` only after both private R2 bindings, entity runtime, execution Git transport and an environment fingerprint are configured. `BACKUP_ENVIRONMENT` must identify the exact account, domains, dispatch namespaces, storage bindings and environment; use different fingerprints in staging and production. Defaults never perform exports.

The scheduler freezes authoritative commands through a persistent pause barrier, drains live turns, exports each entity's private memory and canonical Git repository, and writes a version 2 manifest after all six are complete. Manifest keys are `world/YYYY-MM-DD/<scheduled timestamp>.json`. Git bundles remain in the private builds bucket. The manifest includes authoritative deployment references to retained immutable bundle hashes. Failed backup stays paused and retries the same barrier; it does not publish a partial successful manifest. Paid model/build work cannot start during the pause. Git export is a narrowly authorized maintenance operation, not an inference or deployment allowance bypass.

## Restore

Pause the destination, then POST `/api/v1/backups/restore` with `acknowledgement: RESTORE_WORLD_BACKUP` and a listed manifest key from the operator origin. Environment, population, private payload hashes, Git hashes and live activation prerequisites are validated before mutation. Restore Git histories and all private entity memories, then restore world state. Retained Worker bundles referenced by deployments must remain in the configured private builds bucket; restoring the ledger does not recreate deleted uploaded Workers. A failed restore stays paused behind its persisted permit and can be retried using the identical manifest. Successful restore remains paused for inspection. Memories and operational receipts never enter the public projection.

Legacy world-only snapshots can be parsed by the internal world-state restore helper but are not accepted as complete backups by the operator route.

Focused checks: `pnpm exec vitest run apps/world/features/operations/backup.test.ts` and `pnpm exec vitest run --config vitest.workers.config.ts tests/workers/operations.test.ts`.

Maintenance dispatch requires `BACKUP_ALLOWANCE_USD` above zero in addition to the live world and each entity's allowance. Every new Git/data export or restore reserves a fresh bounded estimate against all three limits before dispatch. Backup retries may reuse a validated immutable export after checking the paused recovery authority; retained reads do not dispatch another paid sandbox or reserve its cost again. Missing exports still reserve a fresh estimate for every attempt. Fixed snapshot/Git/application/manifest failure counters identify the recovery stage without exposing private payloads or provider errors. Unknown costs remain historically reserved across day rollover while daily admission counts their original UTC dispatch day; undated holds remain conservative. `budget.reservedUsd` reports current-day holds and `budget.outstandingReservedUsd` reports all outstanding liabilities; `budget.reconcile` applies independently measured provider costs. Budget configuration and reconciliation remain available during recovery barriers, while work commands and resume stay frozen. An explicit operator pause during backup prevents automatic resumption. Restore merges current usage reservations and preserves current allowance limits, so an older snapshot cannot reset paid spending.

Generated application records and scheduled-job claims are exported as private R2 references and checksummed before restore mutation. Application stores persist their own write freeze to close the gap between cross-service permission checks and snapshots. Successful backup releases those freezes after world resume; restored stores remain frozen until explicit operator resume. Git bundles are currently bounded to 600 KB per canonical repository; application state is bounded by the application's storage quotas. Exceeding a bound fails visibly and leaves the world paused.

Alert webhooks require both `ALERTS_ENABLED=true` and `ALERT_DELIVERY_AUTHORIZED=true`, plus a fixed HTTPS URL and matching `ALERT_WEBHOOK_HOST`. Delivery contains environment and counters only, rejects redirects, suppresses unchanged states and limits delivery to once per hour. Defaults never send alerts. Queue retry/dead-letter counters, projection lag, model failures, entity wake recovery and blocking tasks are available in the private operations view. These local tests do not establish cloud delivery or deployment verification.

Backup invocation depth is bounded: each independent invocation exports at most one missing entity and returns `pending` until the population is complete. Private Durable Object checkpoints retain small ordered entity object references and SHA-256 checksums. Complete memory/Git/application rows live under private R2 progress keys scoped to backup and entity, avoiding the Durable Object value limit for legal large memories. Referenced rows are read, checksummed and validated before continuation/final assembly. Checkpoint scope, identity, checksum and completeness are validated on every resume, including after restart. A later invocation preserves the barrier ID, original creation time and day; a separate seventh invocation writes a complete private manifest and clears the normal backup barrier. A pre-existing barrier without a checkpoint starts at the first entity; execution-side validated immutable export caches remain reusable without another dispatch allowance. Callers must schedule independent continuation invocations rather than loop within one request.

Every successful entity export invocation returns `pending`, including the sixth. The seventh performs finalization alone, leaving headroom for releasing six application freezes. R2 progress objects and final manifests use create-only writes; persisted winning bytes are reread, validated and checksummed before recording a reference or clearing the barrier. A stale invocation cannot overwrite already retained backup bytes. Private progress objects remain separate from the successful-manifest listing.

Live cron dispatch runs one runtime slice per independent invocation. A rotating window inspects at most two residents, stopping after the first safe due slice; assigned residents take priority. This bounds initialization/status RPC overhead and lets every resident lead a window within six minutes. Safe pending personal continuations are eligible on subsequent minutes rather than waiting another thirty minutes; fresh personal work retains that interval. Ambiguous in-flight effects and active leases are excluded, and unfinished shared goals still suppress unassigned personal work. A cron that advances or finalizes backup performs no runtime dispatch, preserving invocation depth for that recovery operation.
