# Extending visitor review

Keep server-selected scope in `GovernanceAction`, construct canonical commands from strict flat decision fields, and validate all corresponding fields after construction. The model must not supply a JSON command or authority identifiers. Never add operator commands or arbitrary execution tools to the governance tool. Preserve independent entity identity from the durable runtime binding.

Task review context only includes safe known build-check labels and canonical evidence identifiers. Actual acceptance review must use `ExecutionGateway.observePublished`; model prose alone is insufficient. Return the explicit inconclusive decision when evidence cannot establish a criterion. Public review reasons and assertions should summarize a decision without hidden reasoning or operational detail.

When editing retry behavior, keep the original command/key before dispatch and only clear it after confirmed delivery. The ordinary continuation and pending tool command belong to the builder lane; governance must preserve both. Add focused tests for scope changes, private revision canaries and exact deployment observation freshness before changing these boundaries.
