# Operating the visitor build loop

Keep simulation as the default. Live inference requires explicit activation, a current release evaluation, valid input/output pricing and positive configured world and entity allowances. Publication remains controlled by the existing isolated build/promotion gates. A visitor suggestion never changes those gates.

Inspect public proposal status, votes and current-goal progress on the slim public website. Use the authenticated operator host for pause, cancellation, overrides and private diagnostics. Changing an accepted visitor goal through operator revision withdraws automated visitor review authority; it must not silently publish the revised private text.

If a task is submitted but waiting, check for a current-revision successful deployment and task-owned build receipt. If completion is waiting, verify the latest project deployment belongs to the selected goal, was authored by someone other than the reviewer, returns successful textual content within the cap and supports each frozen criterion. Interactive criteria require additional real evidence; an agent cannot accept them by repeating their wording.

A timeout, missing published response, oversized page or inconclusive criterion does not replace the active website or advance the queue. Unknown command delivery retains its exact durable key for replay. A world-confirmed stale or rejected governance command is discarded; uncertain delivery retains its exact key for reconciliation. Never claim production readiness from these deterministic tests alone.
